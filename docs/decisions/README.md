| [0032](ADR-0032-credential-provider-interface.md) | Credential providers: one `CredentialProvider` interface (issue, renew, revoke, health) with the host vault as its first implementation and a Vault/OpenBao HTTP backend (KV v2, token roles); host-only configuration entering the policy as the system layer; TTL, scope, audience and renewal rules enforced by the broker; revocation pushed to the provider on revoke, pause, launch end and expiry; outage a named degraded state that fails closed | Proposed; first slice of #267 |
| [0033](ADR-0033-agent-adapter-contract.md) | Agent adapters: one versioned contract (`ward-agent-adapter` 1.0) with a capability-discovery document per adapter, one launch path for Claude Code, Codex and a generic process adapter so missing hooks lower visibility and never authority, the runtime and model recorded as an agent-origin claim, and session launches started from an empty environment | Proposed; first slice of #279 |
| [0034](ADR-0034-node-brokered-credentials.md) | Credentials as node capabilities: a manifest `credentials` grant names a service the node's operator configured, an allowlisted host and a TTL, never a secret; the node leases it through the shared provider interface, bounded by the attempt, injects it only through the attempt's egress proxy, revokes it at the provider when the attempt ends or a restarted node finds it, fails closed by name, and records grants without secrets | Proposed; first node slice of #267 |
| [0035](ADR-0035-node-approval-hold.md) | Approvals as a hold the node enforces: a manifest `hold` names hosts and credential services it already grants; on a node started with `--approval-hold` the attempt's proxy opens one approval request per held capability on its first use and refuses that capability with a named `403` until the control plane's approval of exactly that request is recorded; denial, expiry, cancellation and the attempt's end keep it refused, a pause holds it, the workload can neither open, word nor answer the request, and the existing action and network records carry the evidence | Proposed; implemented under #415 |
| [0036](ADR-0036-node-hosted-agent-adapters.md) | Agent adapters on `ward-node`: the admitted workload names an adapter (`workload.adapter`, outside the capability manifest, so one manifest serves every adapter); a node started with `--agent-adapter <id>` hosts it, advertises `adapters` and refuses any other `unsupported_grant`; the launch is the shared contract's (`catalogue::launch`, the builder sessions use too) and cannot widen the attempt; the provider is reached only through a manifest credentials grant; hook lines become agent-origin claims, a hookless adapter just has less to say; the binding is recorded per attempt as metadata | Proposed; second slice of #279 |
| [0037](ADR-0037-node-agent-shim-and-relay.md) | A real agent runtime on `ward-node`: the operator names a `ward-agent` shim (`--agent-shim`, verified at start, never found beside the node or named by the workload); every hosted adapter's attempt runs under it, bound read-only, so command hooks reach the hook socket; behind an egress proxy its loopback relay forwards to the attempt's proxy and adds no authority; the provider's base URL and a placeholder key point at the relay only for a provider the manifest grants a credential for; a hook's `PermissionRequest` is not bridged, the hold is the approval; amended (§7): every attempt behind an egress proxy runs under the shim for its relay, so a plain workload's stock `git` reaches a credential route as `http://127.0.0.1:3128/<service>/…` | Proposed; third slice of #279 (#424); amended under #267 |
| [0038](ADR-0038-node-mutual-tls-transport.md) | `ward-node` over mutual TLS: an optional `--listen-tls` TCP listener serving the same protocol as the socket over TLS 1.3 only, with the `ward-node` ALPN and no resumption; the node's certificate and key and the client CA (optionally narrowed by SPKI pins) are the operator's files, checked at start; a client certificate replaces the peer-uid gate, never the issuer signature; validity checked with a fixed 60-second skew allowance; handshakes on bounded threads of their own so they never hold the socket; refusals and served clients reported on stderr, rate-limited; rotation is a restart; enrolment, attestation, revocation and a durable handshake record are later slices | Proposed; remote-transport slice of #262 |
